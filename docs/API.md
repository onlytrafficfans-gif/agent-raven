# Phase 1 server interfaces

All application interfaces return JSON unless noted. App-owned JSON responses include the same bounded correlation ID in the `x-request-id` header and response body; unsafe or secret-bearing inbound IDs are replaced. Error responses use `{ error: { code, message, fields?, retryAfter? }, correlationId }`. Except for `/api/health` and Better Auth session endpoints, routes require an authenticated session and a current organization membership. The organization is resolved server-side; clients cannot submit an organization ID.

| Method / path | Authorization | Input | Output | Error categories | Idempotency |
|---|---|---|---|---|---|
| `GET/POST /api/auth/[...all]` | Better Auth | Better Auth registration, email/password, reset-token, and session schemas | Better Auth session responses | framework-standard auth errors | Reset tokens are single-use; successful reset revokes existing sessions |
| `POST /api/account/workspace` | Authenticated account | optional `{ workspaceName }` | membership ID and created flag | validation, unauthorized, setup failure | A unique user-membership constraint and transaction make provisioning retry-safe |
| `POST /api/account/password-reset` | Public, rate-limited by Better Auth | `{ email }` | generic delivery message | validation, email provider not configured | Response does not disclose whether an account exists |
| `POST /api/integrations/apollo` | Owner or Admin | `{ apiKey: string }` | provider, state, lastTestedAt; never the key | validation, invalid credential, insufficient permission, rate limit, provider unavailable | Upsert by organization/provider |
| `DELETE /api/integrations/apollo` | Owner or Admin | none | disconnected state | unauthenticated, forbidden, rate limit, internal | Repeated disconnect remains disconnected |
| `POST /api/search` | Owner, Admin, Analyst | industry/location/employee/revenue ranges, page, perPage | normalized companies, pagination, usage and correlation ID | validation, disconnected/invalid credential, permission, rate limit, budget block, outage | Read operation; every paid attempt records a run/usage outcome |
| `GET /api/companies/:providerId` | Owner, Admin, Analyst | provider organization ID in path | normalized company detail | disconnected, provider errors, rate limit, not found | Explicit user action; Apollo may charge for complete detail according to current entitlement |
| `POST /api/prospects` | Owner, Admin, Analyst | provider identity, retrieved company fields, provenance | prospect plus `created` boolean | validation, identity conflict, rate limit, unauthorized | Idempotent by organization + provider ID and organization + normalized domain; database constraints handle races |
| `GET /api/prospects` | Any member | optional `q`, `status` query | organization-scoped prospects | unauthorized, internal | Safe read |
| `PATCH /api/prospects/:id` | Owner, Admin, Analyst | optional status, note, tags | updated prospect | validation, not found, rate limit, unauthorized | Status and normalized tag replacement are idempotent; notes are append operations |
| `DELETE /api/prospects/:id` | Owner or Admin | none; UI requires explicit confirmation | deleted/suppressed result | unauthorized, forbidden, not found, conflict, rate limit | Transactionally deletes the tenant record and creates durable provider/domain suppression plus a sanitized audit event |
| `GET /api/prospects/export` | Owner or Admin | none | UTF-8 CSV attachment containing up to 5,000 organization-scoped prospects, tags, and notes | unauthorized, forbidden, rate limit, export limit | Safe read of a repeatable database snapshot; each successful export creates an aggregate audit event |
| `POST /api/import/csv` | Owner, Admin, Analyst | multipart `file`, max 2 MB | created/duplicate/error summary and row errors | invalid file, validation, rate limit, unauthorized | Normalized-domain uniqueness prevents duplicates |
| `GET /api/health/live` | Public, sanitized liveness | none | application status and timestamp | none while the process can serve requests | Safe read, `no-store`; does not touch dependencies |
| `GET /api/health` | Public, sanitized readiness | none | app/database status, rounded database latency and warning threshold, non-secret Apollo description | HTTP 503 when database unavailable | Safe read, `no-store`; emits `Server-Timing` and `x-health-status` |

Apollo organization search is currently `POST https://api.apollo.io/api/v1/mixed_companies/search`. Connection testing uses the zero-credit `GET /api/v1/auth/health` endpoint. Organization detail uses `GET /api/v1/organizations/{id}` and can consume one credit; budget authorization should be confirmed before exercising that live path.

Self-service registration creates one isolated organization, an Owner membership, and a disconnected Apollo connection. Password-reset mail is sent through Resend only when `RESEND_API_KEY` and `AUTH_EMAIL_FROM` are configured; secrets never enter browser-delivered code.

Authenticated write, provider, export, and deletion routes use PostgreSQL fixed-window buckets, so enforcement survives application restarts and works across server instances. Apollo search/detail share an organization-wide 10-per-minute allowance; connection tests allow 5 per 10 minutes; disconnects allow 20 per minute; CSV imports allow 10 per minute per user; prospect creates allow 60 per minute per user; prospect updates allow 120 per minute per user; privacy deletions allow 20 per 10 minutes per user; and prospect exports allow 5 per 10 minutes per user. A blocked response is HTTP 429 with matching `Retry-After` header and `error.retryAfter` seconds in the correlated JSON body. Buckets older than 24 hours are removed opportunistically.

The CSV export is intentionally restricted to Owner and Admin roles. It uses the server-resolved organization, records only the format and row count in the audit log, never places credentials or raw provenance in the file, sends `no-store`, and neutralizes cells beginning with spreadsheet formula control characters. CSV responses carry the request correlation ID in the `x-request-id` header rather than a JSON body.

Privacy deletion is intentionally stronger than removing a table row. The Owner/Admin-confirmed transaction removes the prospect, notes, and tag links; removes newly orphaned tags; stores the normalized domain and/or provider identity in the organization suppression table; and appends `PROSPECT_DELETED_AND_SUPPRESSED` with boolean identity evidence only. Subsequent direct saves return `SUPPRESSED`; CSV imports report the suppressed row and do not recreate it. Suppression identities are organization-scoped and are not exposed in ordinary browser responses.
